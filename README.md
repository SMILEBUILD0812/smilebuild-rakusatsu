# 落札くん — SmileBuild 営業ターゲット抽出ツール ＋ 毎日通知

国交省 **全地方整備局**（PPI／各整備局の入札・契約結果）の**工事**落札データを毎日取得して
**「落札くん」で検索・営業管理・CSV出力**でき、**条件に合う新着案件を毎朝メール**するシステム。
測量・建設コンサルタント等の**「業務」は自動で除外し、工事のみ**を扱う。

```
smilebuild-rakusatsu/
├─ index.html          ← 検索・出力ツール（data.json を自動読込）
├─ pipeline.py         ← 取得→蓄積→集計→通知（毎日 GitHub Actions が実行）
├─ requirements.txt
├─ .github/workflows/daily.yml
├─ keishin.csv         ← (任意) 経審マスタ。置くと従業員数・所在地を補強
└─ （自動生成）history.json / data.json / state.json
```

## セットアップ

1. このフォルダを GitHub リポジトリにして push。
2. リポジトリの **Settings → Secrets and variables → Actions** に登録：
   - `SMTP_HOST` `SMTP_PORT`(例 587) `SMTP_USER` `SMTP_PASS` `MAIL_FROM` `MAIL_TO`
   - 任意: `NOTIFY_MIN_YEN`(既定 100000000=1億) `NOTIFY_MAX_YEN`(既定 200000000=2億) `NOTIFY_PREFS`(例 `千葉県,東京都`。空＝全部)
   - 任意: `GBIZ_TOKEN`（所在地・従業員数の自動取得。gBizINFOで無料発行）
   - **データ源の選択（Variables 側／Secrets and variables → Actions → Variables）**：
     - `USE_PPI=1` … PPI(入札情報サービス)の**工事**検索で**全整備局を横断取得**（Playwright自動導入）。推奨。
     - `USE_PPI=0`（既定）… 各地方整備局ページを巡回。`BUREAUS_ONLY=関東,東北` で対象を限定可（空＝全整備局）。
     - `LOOKBACK_DAYS`（既定45）… 何日分さかのぼるか。
   - ※ いずれの源でも、測量・コンサル等の**業務は `is_works()` で自動除外**され、工事のみ残る。
3. **Settings → Pages** で `index.html` を公開（または Xserver に index.html と data.json を一緒に置く）。
   - data.json はリポジトリにコミットされるので、Pages ならそのまま読み込まれる。
4. **Actions** タブで `workflow_dispatch`（手動実行）を一度押して動作確認。

ローカル確認：`python pipeline.py --sample`（ダミーで全工程を通す）→ `index.html` をブラウザで開く。

## 落札くんの手動運用（パイプライン未デプロイでも使える）

`index.html` をブラウザで開き、関東地整からDLした **Excel（.xlsx）/ CSV / JSON** を
画面に**ドラッグ＆ドロップ**（または「ファイル読込」）。複数同時もOK。

- 読み込むたびに**マージして蓄積**され、**この端末に保存**される（閉じても残る）。
- 月次ファイルを足していけば履歴が積み上がる。同じ案件は自動で重複排除。
- 列（落札日・工事名・落札者・落札金額…）は、先頭にタイトル行があっても**自動検出**。
- リセットしたい時は「蓄積を消去」（営業ステータス・メモは残る）。
- ※ **所在地（県・市）・従業員数**は、取り込んだファイルにその列がある場合のみ自動で埋まる。
  無い場合は空欄。`keishin.csv`（経審）を使う P3 突合で後から補強できる。
- ※ 保存はブラウザ容量（数MB）まで。1整備局・年度単位なら十分。長期・大量はパイプラインの history.json が本来の置き場。

## 所在地（県・市）・従業員数の自動補完（会社台帳）

入札結果のExcelには所在地・従業員数が無いことが多い。手作業で調べる代わりに、
**会社台帳（商号・所在地・職員数）**を落札くんに同じ枠でドラッグするだけで、
会社名で自動照合して **所在地（県＋市）・従業員数** を埋める（表記ゆれ＝(株)/株式会社/支店付き等も吸収）。

- 台帳は落札データと**自動で見分けて**取り込む（落札日が無く、商号＋所在地/職員数の列がある＝台帳）。
- 一度入れた台帳は端末に保存され、以後の落札データにも自動適用。
- **入手先**：
  - 従業員数（職員数）＋所在地 → **経営事項審査（経審）の結果データ**（CIIC／各行政庁が公表。商号・所在地・技術職員数・職員数を含む）。
  - 所在地だけなら → **建設業許可業者データ**（各都道府県が公表、CSV/Excelあり）や法人番号公表サイト。
  - パイプライン運用時は `keishin.csv` として置けば P3 で同じ補完が自動で走る。

## 所在地・従業員数を「自動取得」する（gBizINFO・無料API）

手で台帳を集めなくても、**gBizINFO（経済産業省）の無料API**で所在地（県・市）と従業員数を自動取得できる。
1API で両方取れる。約400万法人を収録（※従業員数は公開がある会社のみ入る）。

**今すぐ"見る"手順（約5分）— `enrich_demo.py`**
1. https://info.gbiz.go.jp/ で無料の API トークンを発行（メールで届く）。
2. `companies.txt` に調べたい会社名を1行ずつ書く（落札した会社名でOK）。
3. 実行： `GBIZ_TOKEN=あなたのトークン python enrich_demo.py`
4. 画面に所在地・従業員数が出て、`master_gbiz.json` が出力される。
5. その `master_gbiz.json` を**落札くんにドラッグ** → 取り込んだ落札データの所在地・従業員数が自動で埋まる。

**本番（毎日自動）** — Secrets に `GBIZ_TOKEN` を登録すれば、`pipeline.py` の enrich() が
落札した会社の所在地・従業員数を自動取得して data.json に入れる（落札社だけ照会＋キャッシュ）。

※ なぜブラウザ単体でやらないか：gBiz API はトークンが必要＆CORSでブラウザから直接叩けない。
   取得は手元(Python)／パイプラインで行い、結果を落札くんが表示する設計。

## キャリブレーション（実データに合わせる作業）

実取得の値抜きだけ、実ファイルを見て `pipeline.py` の **★CALIBRATE★** 3 箇所を合わせる：

1. `fetch_results()` … 関東地整の入札結果一覧／PPI 検索結果の「行と列」の取り方。
2. `fetch_bidders()` … 入札調書の「参加業者・入札額」表の取り方（入札参加ランキング用）。
3. `_load_keishin()` … 経審/許可CSVの列名（商号・所在地・職員数）の対応付け。

それ以外（蓄積・集計・data.json生成・差分検知・メール）は完成・動作確認済み。
初回は履歴が空なので、回すほど「過去履歴・年間集計・参加ランキング」が厚くなる。

## マナー

役所サーバーに負荷をかけない：1日1回、リクエスト間隔を空ける（実装済み）、
可能なら検索フォーム連打ではなく公表ファイルのDLを優先。
データ自体は公共の公表情報（政府標準利用規約系）で、利用に制約は少ない。
